# 旅行轨迹记录与规划工具

面向 Windows 的本地旅行路线记录、行程规划与复盘工具。以“旅程 → 日期 → 路段”组织行程，结合地图轨迹、实际记录、评分、照片和道路统计，保存一段旅行从规划到复盘的完整信息。

项目使用 React、TypeScript、Vite、Leaflet、Express 和 Electron。地点搜索、路线规划与省份补查通过本地后端调用高德 Web 服务；旅程及照片索引保存在本机。

> 本文依据当前工作区源码编写，`package.json` 版本为 **0.5.2**。源码功能说明不代表已有 EXE 已包含所有工作区修改；桌面产物内容取决于实际打包时的代码。

### 运行方式的区别

| 运行方式 | 用途 | 数据与能力 |
| --- | --- | --- |
| Windows 便携 EXE | 日常使用 | 内置后端，支持本地照片库和完整 ZIP 备份 |
| 浏览器开发页 | 前端开发与调试 | 需要同时运行后端；使用当前浏览器存储，备份为 JSON |
| 源码 Electron：`npm.cmd run desktop` | 桌面开发与调试 | 构建后启动 Electron；默认数据目录和端口与正式包不同 |
| 只读演示页 | 展示示例路书 | 从静态分片加载演示数据，禁用写操作 |

应用以本地单用户使用为目标，没有账号登录或云端自动同步。地图底图、地点搜索、新路线计算和省份补查需要网络；已保存的记录与路线缓存不能代替离线底图库。

## 快速开始

### 使用 Windows 桌面版

1. 获取已打包的 Windows x64 便携 EXE，双击运行，无需另外安装 Node.js。
2. 首次使用时配置**高德 Web 服务 Key**。地图使用 Leaflet，所需的是后端 Web 服务 Key。
3. 选择“规划”或“复盘”，创建旅程并设置起止日期。
4. 按日期添加路段，在地点联想中选择起点、终点和途经点，再计算路线。
5. 旅行结束后转入复盘，补充实际记录、评分、标签、备注及照片。
6. 打开“数据统计”查看累计信息，定期通过“备份”菜单导出完整备份。

`Ctrl + Shift + B` 可快速导出备份。复制 EXE 本身不会复制用户数据或原始照片。

### 从源码启动

在项目根目录打开 PowerShell：

```powershell
npm.cmd ci
Copy-Item .env.example .env.local
```

编辑 `.env.local`，填入自己的高德 Web 服务 Key，然后运行：

```powershell
npm.cmd run dev
```

默认前端地址为 `http://localhost:5173`，后端监听 `http://127.0.0.1:3001`。已有 `.env.local` 时直接编辑该文件，避免覆盖现有配置。完整环境说明见[本地开发](#本地开发)。

## 旅程管理与路线编辑

### 旅程、日期与路段

- 旅程按“复盘 / 规划”分类，支持新建、编辑、删除、排序及创建独立副本。
- 路段按日期组织，支持添加、编辑、删除和排序。
- 可以插入或删除一天，并相应调整后续日期。
- 可记录路段风景评分、驾驶难度、天气/路况/感受等复盘标签及文字备注。
- 实际里程、实际耗时和实际过路费为可选记录；未填写不会作为零值参与统计。

### 地点与路线

- 输入地名后，从高德联想结果选择具体地点，使名称与坐标对应。
- 起终点之间可加入多个途经点，并调整顺序。
- 驾车支持“高速优先”“速度优先”“避免收费”；骑行使用独立路线接口。
- 缺少有效坐标的途经点会阻止正式计算，避免悄悄跳过地点。
- 地图支持起终点、轨迹控制点及照片位置的交互调整。
- 规划结果包含轨迹、里程，以及上游返回的预计时间和收费信息。缺失项保留为待补全。

路线几何和道路分析保存在 IndexedDB。路线关键参数变化后，旧分析可能标记为过期；**能显示旧轨迹不等于道路分析仍有效**。

### 地图范围与着色

地图可查看全部旅程、当前旅程、日期或路段。起终点标记随当前显示范围确定。

| 着色方式 | 含义 |
| --- | --- |
| 默认 | 常规路线浏览 |
| 风景 | 依据路段风景评分 |
| 难度 | 依据路段驾驶难度评分 |
| 道路类型 | 按道路片段显示高速、国道、省道和其他道路；待核实部分单独处理 |

道路类型模式支持类别显隐。道路分类来自路线分析及人工修正，不代表实时路况，也不是车辆实测轨迹的自动识别结果。

## 数据统计与道路分析

### 统计范围

“数据统计”汇总**复盘旅程**，规划中的旅程不会混入历史总览。可选择全部复盘旅程、某一年或具体旅程；年份按旅程开始日期归档。

统计包含：

- 旅程数、路段数、规划与实际里程、预计与实际驾驶时间、旅行天数。
- 逐旅程明细及数据完整性，支持按日期、里程、时间等字段排序。
- 规划/实际里程档位、自然日档位、预计/实际驾驶时间档位。
- 风景与难度评分分布，以及按里程加权的平均分。
- 道路构成、命名道路及本次与历史累计对照。

旅程明细默认按开始日期升序排列；无效或缺失日期放在有效日期之后。

### 统计口径

| 指标 | 计算与展示原则 |
| --- | --- |
| 规划与实际 | 独立汇总，不用预计值填充实际记录 |
| 缺失数据 | 显示“待补全”或完整性状态，不将缺失解释为 0 |
| 部分合计 | “已记录”表示仅覆盖已有数据的路段 |
| 旅行天数 | 按起止日期计算，包含首尾两天；同日往返为 1 天 |
| 评分均值 | 按有评分且里程已知的路段进行里程加权；未评分不作为最低分 |
| 评分里程占比 | 分母为已评分且里程已知的路段里程 |
| 道路里程 | 来自规划路线分析；人工区间分配或几何估算保留来源，不冒充实测里程 |
| 道路表占比 | 当前与历史分别以各自规划总里程为分母；搜索、道路类别和省份筛选不会改变分母 |
| 历史累计 | 全部复盘旅程的累计，包含当前选中的复盘旅程 |
| 涉及旅程数 | 按旅程去重；同一旅程多次经过某条道路只计 1 个旅程，里程仍累计 |

同一路线的多次经过会累计里程，所以历史道路里程不等于地图上去重后的道路长度。

### 道路类别与名称

内部分类包括高速公路、国道、省道、县道、乡道、村道、城市道路、其他道路及未知道路。地图和道路构成摘要使用更集中的四类展示，并保留未分类信息。

命名道路表支持按名称、编号、省份搜索及按类别、省份筛选：

- 高速、国道和省道按道路身份汇总。
- **省道按省份区分**，例如不同省份的 `S101` 不应直接合并。
- 省份待确认、无编号省道独立列出，不自动并入已知省份。
- 展示名称可以简化，但保留可展开的历史记录名称及原名搜索。
- 名称中出现其他道路编号时保留冲突提示，不仅凭显示名称自动改写身份。
- 在年份或单旅程范围内，默认突出当前经过的道路；可选择“显示其他历史道路”。

### 历史路线分析与人工修正

旧缓存可能只有轨迹，没有道路类别或省份信息。可主动运行“历史路线道路分析”，按当前路段、当前旅程或全部复盘旅程补全。

补全过程会重新请求路线，并比较新旧总里程和几何：

1. 路线相似时，补充道路分析。
2. 差异较大时，由用户决定保留原轨迹还是明确替换。
3. 界面展示成功、待确认、失败、跳过和取消等状态，并支持取消任务。

补全会调用高德服务，不能保证上游今天返回的路线与历史路线完全相同。省份补查依据道路片段的导航信息或折线位置；证据不足或存在跨省冲突时保留待确认状态。

人工处理包括：

- 在道路片段表中修正道路类别、编号和省份。
- 勾选多段、Shift 连选或框选后批量编辑、保存。
- 对纯轨迹在地图上依次选择区间起终点，保存道路标注；未标注部分保持未知，原始轨迹不变。
- 保留人工标注及距离来源信息，便于后续解释统计结果。

## 照片库与游记

### 桌面照片库

照片库在 **Electron 桌面版的复盘工作区**启用。普通浏览器页不具备相同的本地文件访问能力。

- 每个旅程可登记一个照片库目录，递归扫描子目录；不同登记目录不能相互重叠。
- 支持 JPEG、PNG、WebP，单张文件上限 100 MiB；HEIC/HEIF 需先转换。
- 只关联原图路径，不把原图复制进旅程数据。
- 提取拍摄时间、方向和 GPS 等 EXIF 信息，生成本地 WebP 缩略图。
- 中国境内照片 GPS 的 WGS-84 坐标会转换为地图使用的 GCJ-02 坐标。
- 支持候选照片筛选、批量关联到路段、前后查看、备注、旅程封面和路段间移动。
- 地图支持照片标记、聚合显示、手动定位、清除位置及恢复 EXIF 位置。
- 原图移动、缺失或内容改变后，可重新扫描、重新关联及刷新元数据和缩略图。
- 提供照片关联一致性检查与修复。

移除照片关联、移除目录登记或删除旅程不会删除本地原图。原图仍需单独备份。

### 路书与 Markdown 游记

在复盘的路书浏览中打开旅程，可浏览逐日路线、照片和旅程统计，并生成游记。

游记由已有记录按规则组织为 Markdown，包含日期、地点、途经点、规划与实际记录、评分、标签、备注及照片数量等信息；缺失内容会省略。它不是调用大语言模型生成的旅行经历。

支持预览、重新生成、保存到旅程和下载 Markdown。已保存游记随旅程备份导出。

## 备份与恢复

### 备份内容

| 内容 | 桌面 ZIP | 浏览器 JSON |
| --- | --- | --- |
| 旅程、日期、路段、评分、备注和实际记录 | 包含 | 包含 |
| 已保存游记 | 包含 | 包含 |
| 路线缓存、道路片段及分析元数据 | 包含 | 包含 |
| 照片库登记、照片索引和缩略图 | 包含 | 不包含 |
| 本地原图 | 不包含 | 不包含 |
| 高德 Key | 不包含 | 不包含 |

当前旅程备份格式为 **V3**，兼容导入 V1、V2、V3 和原始 `TripReview` JSON。桌面 ZIP 外层清单版本仍为 V1，与内部旅程 JSON 的 V3 是两个不同版本号。

桌面归档实现限制：旅程 JSON 为 512 MiB，ZIP 导入文件为 1 GiB，累计解压内容为 2 GiB。上述是文件处理上限，不代表任意接近上限的数据都能在所有机器上流畅处理。

### 恢复行为

**导入是恢复替换，不是追加合并。**

- 完整 ZIP 恢复会替换当前全部旅程、路线缓存、照片索引和缩略图。
- JSON 恢复会替换旅程和路线缓存；旧 JSON 不包含桌面照片索引及缩略图。
- 完整恢复先校验结构，并在写入失败时尝试回滚；导入前仍应导出当前备份。
- 路径变化后，照片索引需要重新关联本地目录或原图。

换电脑时，先导出 ZIP，再单独复制照片库目录；在新电脑导入备份、配置 Key，并根据需要重新关联照片目录。

## 数据保存位置

### 正式 Windows 包

当前标准打包配置使用以下兼容数据目录：

```text
%APPDATA%\roadtrip-retrospective-tool-photo-album-preview\
├── amap-key.json          高德 Web 服务 Key 配置
├── photo-library.json     照片库登记与照片索引
├── photo-thumbnails\      缩略图缓存
├── Local Storage\         旅程结构数据
└── IndexedDB\             路线缓存和道路分析
```

目录名保留了相册实验阶段的命名，是当前运行配置的兼容行为。

| 桌面运行配置 | 默认端口 | 用户数据目录 |
| --- | --- | --- |
| 标准打包 EXE | `41874` | `%APPDATA%\roadtrip-retrospective-tool-photo-album-preview` |
| 相册实验包 | `41874` | 与标准包相同 |
| 源码 `npm.cmd run desktop` | `41873` | Electron 默认目录，通常为 `%APPDATA%\roadtrip-retrospective-tool` |
| P0 修复测试包 | `41875` | `%APPDATA%\roadtrip-retrospective-tool-p0-fixes-test` |

正式包与相册实验包共享数据目录和端口，不应同时运行。便携 EXE 表示免安装，**不表示数据保存在 EXE 同级目录**。

`ROADTRIP_DESKTOP_PORT` 可覆盖桌面端口，但端口也是网页存储 Origin 的一部分。仅改变端口不能完整隔离照片索引等文件数据，不宜作为日常切换数据的方式。

### 浏览器存储

| 数据 | 保存位置 |
| --- | --- |
| 旅程结构 | localStorage：`trip-review-data-v1` |
| 损坏数据恢复副本 | localStorage：`trip-review-data-v1-recovery-copy` |
| 路线与道路分析 | IndexedDB：`trip-route-cache`，数据库版本 2，对象仓库 `segmentRoutes` |

浏览器存储按协议、主机名和端口隔离。`localhost` 与 `127.0.0.1`、不同端口、不同浏览器配置都可能对应不同数据。

检测到损坏的旅程 JSON 时，应用尝试隔离原文、停止自动覆盖并显示恢复提示。应先导出恢复原文，再处理损坏数据。

## 本地开发

### 环境

- Windows x64：主要开发与正式打包平台。
- Node.js 与 npm：本次文档核对环境为 Node.js `24.14.0`。测试直接导入 `.ts` 文件，需要支持默认 TypeScript 类型剥离的 Node.js；使用同一主版本环境可减少兼容差异。
- 高德 Web 服务 Key：用于地点联想、驾车、骑行和逆地理编码。

PowerShell 中使用 `npm.cmd`，避免部分机器上 `npm.ps1` 的执行策略问题。

### 环境变量

根目录 `.env.example` 提供配置模板：

```dotenv
AMAP_WEB_API_KEY=your_amap_web_service_key
BACKEND_PORT=3001
VITE_BACKEND_BASE_URL=http://localhost:3001
VITE_APP_MODE=normal
```

| 变量 | 说明 |
| --- | --- |
| `AMAP_WEB_API_KEY` | 后端使用的高德 Web 服务 Key |
| `AMAP_WEB_KEY` / `AMAP_KEY` | 旧 Key 变量名兼容；优先级低于 `AMAP_WEB_API_KEY` |
| `BACKEND_PORT` | 开发后端端口，默认 `3001` |
| `VITE_BACKEND_BASE_URL` | Vite 的 `/api` 代理目标，应与后端一致 |
| `VITE_APP_MODE` | `normal` 或 `readonly-demo`，启动/构建时读取 |
| `ROADTRIP_DESKTOP_PORT` | Electron 内置服务端口覆盖，仅在有明确需要时使用 |

后端加载 `.env` 和 `.env.local`，后读取的配置可覆盖先前值。桌面版可在应用内持久保存 Key；启动时环境配置的 Key 优先于本地保存的 Key。

浏览器开发模式下，在界面设置 Key 只影响当前后端进程；需要持久配置时编辑 `.env.local`。不要将 Key 写入 `VITE_*` 变量或提交到仓库。

## 本地接口与安全边界

前端通过 `/api` 访问本地服务；Vite 开发与预览模式代理到配置的后端，桌面版则由内置服务同时提供静态页面和接口。

| 接口 | 用途 |
| --- | --- |
| `GET /healthz` | 本地后端健康检查 |
| `GET /api/config/amap-key` | 查询 Key 是否已配置，不返回 Key 内容 |
| `POST /api/config/amap-key` | 设置 Key |
| `GET /api/amap/inputtips` | 地点联想 |
| `GET /api/amap/direction` | 驾车路线 |
| `GET /api/amap/cycling-direction` | 骑行路线 |
| `GET /api/amap/regeo` | 逆地理编码与省份补查 |

开发后端与桌面服务监听 `127.0.0.1`。`/api` 要求 `X-Roadtrip-Client: roadtrip-local-app`；请求带 Origin 时还需符合允许列表。默认开发来源为 `localhost` 或 `127.0.0.1` 的 `5173`、`4173` 端口。该固定标识是本地请求约束，不是用户认证系统。

照片 IPC 校验桌面来源，并限制在授权目录内读取；扫描跳过符号链接及目录联接。外部链接限定为 HTTP/HTTPS。

Key 在后端使用，桌面配置保存在本机 JSON 中，并非加密凭据库。应用不会将其写入前端构建，但调用高德时会向高德发送 Key 及所需地点/坐标信息。不要公开用户数据目录、Key 配置或包含私密地点的演示数据，也不要直接把本地后端暴露到公网。

## 常见问题

### 地点搜索或路线规划失败

检查 Key 类型与配置、后端是否启动、网络及高德接口返回信息。地点输入后应选择联想候选，仅有名称而缺少坐标的途经点会阻止规划。

开发时可检查后端是否在线：

```powershell
Invoke-RestMethod http://127.0.0.1:3001/healthz
```

该检查只证明本地服务在线，不证明 Key 有效或高德服务可用。

### 前端打开了，但接口返回 403

检查前端实际端口及访问主机名。Vite 遇到端口占用可能使用其他端口，而后端默认来源列表只包括 `5173` 和 `4173`。也应确认请求带有应用客户端标识。

### 地图有轨迹，统计却显示待补全

旧路线缓存可能只有几何点，没有道路分析，或分析已与当前参数不匹配。先检查数据完整性，再主动运行历史路线道路分析；不要将“待补全”理解为零里程。

### 同一个省道编号出现多行

省道编号需要结合省份识别，不同省份的同编号道路会分开统计。待确认省份和无编号省道也保留独立记录，可检查证据后人工修正。

### 开发版和正式 EXE 中的旅程不同

它们默认使用不同端口和用户数据配置。浏览器的主机名、端口也影响存储隔离。需要迁移时使用备份导出与导入，不要仅靠修改端口寻找数据。

### 没有照片库入口，或原图显示缺失

照片库需要 Electron 桌面复盘环境。原图目录移动后重新关联目录；单个文件移动后重新扫描并关联；文件内容变化后刷新元数据和缩略图。

### 导入备份失败

确认导入文件是支持的 JSON 或完整 ZIP，文件未损坏且未超过限制。桌面 ZIP 的内部旅程 JSON 支持 V1/V2/V3；不要通过手改版本号绕过格式校验。失败后保留原备份与当前数据，依据界面错误定位原因。

### `npm.cmd test` 无法导入 `.ts`

检查 `node --version`。当前测试直接导入 TypeScript 源文件，应使用支持默认类型剥离的 Node.js 环境；不要仅因旧 Node.js 不支持而改写项目代码。

### 打包出现 `spawn powershell.exe ENOENT`

先检查可执行文件与 PATH：

```powershell
Get-Command powershell.exe -ErrorAction SilentlyContinue
$env:PATH
```

确认系统 PowerShell 存在但路径缺失后，可仅在当前会话补充：

```powershell
$env:PATH = 'C:\Windows\System32\WindowsPowerShell\v1.0;' + $env:PATH
```

### 打包出现 `EPERM`、`EBUSY` 或 `win-unpacked` 占用

先检查本次开发自行启动的 Electron、预览服务或 watcher，再定位具体占用。不要删除整个 `release`、关闭所有 Node/Electron 进程或直接更改构建架构。完成最小处理后标准流程只重试一次；仍失败时保留错误信息并重新判断根因。
